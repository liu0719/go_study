## git修改提交路径
```bash
git config --global --unset http.proxy    # 关梯子
git config --global http.proxy http://127.0.0.1:10808   # 开梯子后恢复,端口为梯子的端口
```
## git文件忽略跟踪
在跟目录`.git`同级文件夹下新建`.gitignore`在该文件中配置要忽略的文件和文件夹

> eg：
```gitignore
# 文件夹名，也可以用路径名
.vscode
.obsidian
/docs/
```

## 撤销上一次提交（提交后发现备注写错了）

最常用的一条：

```bash
git reset --soft HEAD~1
```

**先把两个词搞懂：**

- `HEAD`：你现在站着的"这一格"，也就是最近一次提交。`HEAD~1` 就是往回走一格，指上一条提交（`HEAD~2` 就是往回两格）。
- `--soft`：**只退提交记录，不碰你写的代码**。——接下来直接 `git commit` 就能重新提交。

**三个选项的区别，可以想成"退房退到哪一步"：**

| 参数 | 提交记录 | 暂存区（git add 过的） | 工作区（文件内容） | 什么时候用 |
|---|---|---|---|---|
| `--soft` | 撤销 | 保留 | 保留 | 备注写错、漏加文件，想重新 commit（**最安全，拿不准就选它**） |
| `--mixed` | 撤销 | 清空（改动退回未 add 状态） | 保留 | 想重新挑选要提交哪些文件 |
| `--hard` | 撤销 | 清空 | **清掉，恢复成提交前的样子** | 代码写废了彻底不要（**会丢代码，慎用**） |

> 一句话记：`--soft` 只退记录，`--hard` 连代码一起退。

**只想改备注、内容完全不动（还没 push 时更省事）：**

```bash
git commit --amend -m "正确的备注"
```

`amend` 就是"修补上一次提交"，直接改写上一条提交的备注，不会产生新提交。
> 注意：已经 push 到远端的提交，`reset` / `amend` 都会让本地历史和远端对不上（分叉），需要 `git push -f` 强制覆盖。多人协作时先跟别人说一声，免得覆盖掉别人的提交。

**只是取消暂存（这个文件不想提交了，但代码留着）：**

```bash
git restore --staged <文件名>   # 新写法
git reset HEAD <文件名>          # 旧写法，效果一样
```

文件内容一个字都不会变，只是从暂存区拿出来放回工作区。
